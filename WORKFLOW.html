System architecture

End-to-end flow

One trigger, then eight automated steps. No human clicks between submit and a merged, live site.

Trigger — client completes the wizardG99

On Part-2 submit, OnboardingWizardService’s after-commit hook calls WebsiteBuildNotifierService, which POSTs a JSON webhook (business + answers) to the tool with X-Webhook-Secret. Fail-soft: a webhook error never breaks the client’s submit. One retry after 90s covers Render cold-start.

Intake — webhook → queued jobTOOL

POST /api/webhook/onboarding-submitted validates the secret, maps G99 question_keys to the tool schema (incl. site_love_1_url → design reference), returns 202, and queues a job (deduped by draftId, one at a time).

CRO audit — existing siteGEMINI

Scores the client’s current site (vision / UX / CRO / content) — the “before” benchmark and the list of what to fix.

Compose the build promptGEMINI

Scans the reference site the client loves (e.g. ruma.com) for its design language, folds in the CRO findings + full onboarding + imagery direction, and writes a detailed brand system + build brief.

Generate 4 pagesSTITCH

One project + design system → Home / Treatments / Team / Contact generated in parallel. Post-processing fixes broken images, swaps text-in-image, injects SEO + a consistent nav.

Assemble the siteGEMINI

Binds the pages into one coherent bundle with shared AI chrome (nav/footer), rewires links → a previewable /site/.

WordPress theme + open PRGITHUB

Builds a classic PHP theme (index.php + style.css + page templates) plus a must-use plugin that auto-activates the theme and provisions Pages + menu on deploy. Clones prodteam, writes to web/app/themes/g99-<slug>/, pushes a unique branch, opens a PR.

CI watch → auto-fix → auto-mergeGITHUB

Polls the PR’s build checks every 10s (integration test ignored). On a Pint failure it feeds the CI log to Gemini, commits the corrected file, and re-checks (max 3). When green → squash-merge + delete branch.

Activation watchWORDPRESS

main → FlyWP deploy. Polls the live site until /themes/g99-<slug>/ appears in the HTML — the signal the mu-plugin has activated the theme.

After-audit + comparisonGEMINI

Re-runs the CRO audit on the live site, computes the before→after delta, writes a self-contained report (/reports/<id>.html) and posts the score table as a PR comment (the durable copy — Render’s disk is ephemeral).

Known constraints & gotchas

  • Render free tier sleeps after ~15 min idle. A background job makes only outbound calls, so keep /jobs open (its poll keeps the instance awake) or use a paid tier for unattended runs.
  • Ephemeral disk. Generated files and /reports/* are wiped on restart/deploy — the PR comment is the durable record.
  • Stitch is flaky and returns a generic “invalid argument” for many issues; every call is retried, deviceType is forced UPPERCASE, and the model is pinned (default is deprecated).
  • WordPress pages live in the DB, not Git — hence the mu-plugin that provisions Pages/menu on init (a programmatic theme switch does not fire after_switch_theme).
  • Merge to main = production. Webhook-triggered runs auto-merge; only the build checks gate it (integration test is intentionally ignored).
  • Repo is currently public — no secrets in it, but consider making it private.
